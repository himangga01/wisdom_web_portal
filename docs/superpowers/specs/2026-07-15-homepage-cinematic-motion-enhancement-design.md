# 홈페이지 시네마틱 모션 강화 설계

- 상태: 사용자 방향 승인, 작성 문서 검토 단계
- 대상: `prototypes/homepage-motion`
- 작성일: 2026-07-15
- 전달 형식: 서버 없이 실행 가능한 단일 HTML

## 1. 변경 목표

현재 추천 조합 홈페이지의 신뢰감과 정보 구조는 유지하면서 사용자가 체감하는 움직임을 약 50% 늘린다. 사용자가 선택한 방향은 효과 수와 강도를 함께 높이는 `시네마틱형 B안`이다.

이 문서는 기존 `2026-07-15-homepage-scroll-motion-design.md`에서 정한 8개 모션 예산과 600ms 기본 시간을 다음 기준으로 대체한다. 기존의 자바스크립트 실패 복구, 모션 감소, 키보드 접근성, 가로 넘침 방지와 성능 기준은 그대로 유지한다.

성공 기준은 다음과 같다.

- 관찰 대상은 정확히 12개이며 모두 페이지를 연 뒤 최초 한 번만 재생한다.
- 사진 마스크, 텍스트 리빌, 카드 스태거와 스크롤 진행선이 차분한 하나의 시각 언어로 보인다.
- 링크·버튼·업무 선택지는 애니메이션 전에도 읽고 조작할 수 있다.
- 모바일에서는 이동량과 시차를 줄여 콘텐츠 탐색 속도를 해치지 않는다.
- 모션 감소 설정, 자바스크립트 오류와 `IntersectionObserver` 미지원 시 첫 프레임부터 모든 콘텐츠가 보인다.
- 최종 데모는 CSS·JavaScript·대표 사진을 포함한 단일 `.html` 파일로 제공한다.

## 2. 선택한 시각 방향

### 2.1 시네마틱 리빌

- 비상호작용 제목은 아래에서 천천히 올라오며 약한 흐림이 사라진다.
- 대표 사진은 미세 확대 상태에서 원래 크기로 돌아오며 세로 마스크가 열린다.
- 같은 역할의 카드들은 100ms 간격으로 순차 정렬된다.
- 섹션 리빌은 위·아래 방향을 교차해 긴 페이지의 단조로움을 줄인다.
- 페이지 상단에는 현재 읽은 위치를 보여주는 2px 골드 진행선을 둔다.
- 카드와 업무 선택지는 포인터가 올라오면 짧게 반응한다.

### 2.2 사용하지 않는 효과

- 무한 반복, 자동 재생 문구, 바운스와 큰 회전
- 배경과 본문이 크게 엇갈리는 패럴랙스
- 글자 단위 분해 애니메이션
- 레이아웃을 변경하는 `top`, `left`, `height` 애니메이션
- 한 요소에서 두 번 이상 재생되는 스크롤 모션

## 3. 모션 토큰

| 토큰 | 값 | 용도 |
|---|---:|---|
| `duration-cinematic` | 900ms | 제목과 일반 콘텐츠 |
| `duration-media` | 780ms | 대표 사진 확대·마스크 |
| `duration-interaction` | 220ms | 호버·포커스 반응 |
| `distance-desktop` | 32px | 데스크톱 리빌 이동 |
| `distance-mobile` | 16px | 모바일 리빌 이동 |
| `media-scale` | 1.035 → 1 | 사진 깊이감 |
| `text-blur` | 6px → 0 | 비상호작용 제목 |
| `stagger-card` | 100ms | 동일 그룹 카드 간격 |
| `stagger-max` | 200ms | 세 번째 카드의 최대 지연 |
| `ease-cinematic` | `cubic-bezier(0.16, 1, 0.3, 1)` | 느리게 정착하는 감속 |

카드 그룹의 최대 완료 시간은 1,100ms다. 모바일에서는 카드 간격을 60ms, 최대 지연을 120ms로 줄이고 `text-blur`를 사용하지 않는다.

### 3.1 초기 시각 상태

`.motion-enabled`가 정상 등록된 뒤에만 다음 초기 상태를 적용한다.

- 일반 제목: `opacity: 0.12`, `translateY(32px)`, `blur(6px)`
- 첫 화면 제목·설명: `opacity: 0.35`, `translateY(24px)`, `blur(4px)`이며 상담 링크에는 적용하지 않는다.
- 대표 사진: `opacity: 0.55`, `scale(1.035)`, `clip-path: inset(7% 0 9% 0)`
- 링크가 포함된 카드 그룹과 업무 선택 패널: `opacity: 1`을 유지하고 위치만 이동한다.
- 대표 이력의 네 칸: 65ms 간격을 사용해 네 번째 칸도 195ms 안에 시작한다.

모바일에서는 제목과 사진의 초기 투명도를 각각 0.55와 0.7로 높이고 흐림을 제거한다.

## 4. 관찰 대상 12개

1. **첫 화면 문구 그룹**: 제목·설명만 리빌하고 상담 링크는 계속 완전히 보이게 유지한다.
2. **대표 사진**: 확대, 투명도와 세로 마스크를 함께 전환한다.
3. **세 전문영역 카드**: 기업행정·공공조달·출입국·비자를 100ms 간격으로 이동시킨다.
4. **업무 찾기 안내 문구**: 아래에서 위로 리빌한다.
5. **업무 선택 패널**: 패널은 이동만 적용하고 입력·라벨·상담 링크의 투명도는 변경하지 않는다.
6. **업무 원칙 제목**: 아래에서 위로 리빌한다.
7. **업무 원칙 카드**: 세 카드를 순차 리빌한다.
8. **전문정보 제목**: 위에서 아래로 리빌해 앞 섹션과 리듬을 구분한다.
9. **전문정보 카드**: 세 카드를 순차 리빌한다.
10. **대표 이력 그룹**: 네 칸을 왼쪽에서 오른쪽 순으로 정렬하되 전체 지연은 200ms를 넘지 않는다.
11. **상담 섹션 문구**: 아래에서 위로 리빌한다.
12. **사무소 연락처 카드**: 이동과 약한 확대만 적용하고 모든 링크는 계속 보이게 유지한다.

헤더, 메뉴, 언어 선택, 푸터에는 관찰 기반 리빌을 추가하지 않는다.

## 5. 보조 효과

### 5.1 스크롤 진행선

페이지 최상단에 `position: fixed`인 2px 골드 선을 둔다. CSS Scroll-driven Animations를 지원하는 브라우저에서만 `animation-timeline: scroll(root)`로 가로 비율을 갱신한다. 지원하지 않는 브라우저에서는 진행선을 숨기며 별도 스크롤 이벤트를 등록하지 않는다.

### 5.2 카드 상호작용

- 전문영역·업무 원칙·전문정보 카드는 호버 시 `translateY(-6px)`와 약한 그림자를 적용한다.
- 전문영역의 원형 화살표는 30도 회전한다.
- 업무 선택 라벨은 호버 시 `translateX(4px)` 이동한다.
- `:focus-visible`과 `:focus-within`에서는 효과보다 명확한 포커스 윤곽선을 우선하며 콘텐츠를 즉시 최종 상태로 만든다.

## 6. 상태와 오류 복구

기존 `reveal-controller.ts`의 단방향 상태 모델을 유지한다.

1. HTML의 모든 대상은 기본 상태에서 완전히 보인다.
2. 모션 감소 설정과 Observer 지원 여부를 확인한다.
3. Observer 생성과 12개 대상 등록이 모두 성공한 뒤 `.motion-enabled`를 마지막에 추가한다.
4. 교차한 대상은 `data-revealed="true"`가 되고 다시 숨겨지지 않는다.
5. 포커스, 직접 해시, BFCache 복귀와 화면 회전 시 해당 대상을 즉시 최종 상태로 만든다.
6. 초기화 중 예외가 발생하면 `.motion-enabled`를 제거하고 전 대상을 최종 상태로 복구한다.

초기 은닉 규칙은 계속 `prefers-reduced-motion: no-preference` 안에서만 선언한다. 모션 감소 설정에서는 진행선과 모든 전환을 제거한다.

## 7. Tailwind와 CSS 구성

- Tailwind CSS v4 로컬 빌드와 `@tailwindcss/vite`를 유지한다.
- 모션 토큰은 `src/styles.css`의 CSS 사용자 정의 속성으로 선언한다.
- 공통 최종 상태, 시네마틱 텍스트, 미디어 마스크, 상호작용 그룹과 카드 스태거를 분리된 선택자로 구성한다.
- 애니메이션 속성은 `opacity`, `transform`, `filter`, `clip-path`로 제한한다.
- 대표 사진에는 흐림 필터를 사용하지 않는다.
- 모바일에서는 필터를 제거하고 이동거리·시차를 줄인다.

## 8. 성능·접근성 기준

- 320, 390, 768, 1024, 1440px에서 가로 넘침이 없어야 한다.
- 모든 키보드 포커스 대상의 가장 가까운 리빌 컨테이너는 포커스 전에 최종 상태가 되어야 한다.
- 무자바스크립트와 Observer 오류 상황에서 모든 콘텐츠의 계산된 투명도는 1이어야 한다.
- 로컬 실험실 CLS는 0.1 이하, LCP는 2.5초 이하여야 한다.
- 일반 모션과 모션 감소 설정의 LCP 중앙값 차이가 100ms를 넘으면 대표 사진의 확대를 제거한다. 마스크는 유지하되 LCP에 영향을 주면 함께 제거한다.
- 진행선은 접근성 트리에서 제외하고 콘텐츠 의미를 전달하는 용도로 사용하지 않는다.

## 9. 테스트 변경

- 정적 계약의 모션 대상 수를 8개에서 12개로 변경한다.
- 12개 키의 고유성과 새 대상 네 개를 검사한다.
- 각 대상의 상태 변경이 한 번뿐인지 Chromium에서 검사한다.
- 카드 스태거가 200ms 상한을 넘지 않는지 계산된 스타일로 검사한다.
- `prefers-reduced-motion`, Observer 미지원·생성 예외, 무자바스크립트, 키보드 포커스, 직접 해시와 화면 회전 검사를 유지한다.
- 반응형 너비, CLS·LCP와 사진 모션 회귀 검사를 다시 실행한다.

## 10. 단일 HTML 데모

`npm run standalone`은 운영 빌드 이후 다음 내용을 하나의 파일에 포함한다.

- 컴파일된 Tailwind CSS
- 번들된 모션 JavaScript
- Base64 데이터 URL로 변환한 대표 사진

출력 파일명은 `.superpowers/brainstorm/renders/wisdom-homepage-cinematic-demo.html`이다. Chromium에서 `file://`로 직접 열어 제목 표시, 12개 대상의 최초 1회 재생, 390px 가로 넘침 없음과 콘솔 오류 0건을 확인한다.

## A. 공개 포털

### High 3건

1. **상담 페이지 안내문에 개발자 내부 언어 노출** — `consultationIntro`가 4개 언어 모두 "이 화면은 실제 API로 전송하며 성공 결과를 미리 표시하지 않습니다" 같은 문구. 일반 방문자에게 의미 불명이고 불신 유발. → 생활 언어로 교체 필요.
2. **동의 문서 로딩 중 표시 없음** — 페이지 진입 직후 동의 체크박스·제출 버튼이 `disabled`인데 로딩 중이라는 가시적 안내가 없음(`aria-busy`만 설정, 대응 CSS/텍스트 없음). 느린 모바일 회선에서 "왜 체크가 안 되지"를 겪게 됨.
3. **브론즈 색 텍스트 대비 미달** — `#a78d6c` 대 ivory/white 배경이 **3.10:1**로 WCAG AA(4.5:1) 미달. 인사이트 메타, 게시일, 서비스 카드 라벨 등 작은 텍스트에 사용 중. 고령·저시력 사용자에게 실질적 장애.

### Medium 8건

4. **모바일에서 언어 전환 발견 불가** — 700px 이하에서 언어 링크가 햄버거 메뉴 최하단에만 존재하고 크기도 약 11.5px. 다국어 방문자가 주 타깃인데 첫 화면에 언어 전환 수단이 없음.
5. **제출 성공 후 기대치 안내 부재** — "접수되었습니다. 접수번호: …"뿐, 누가·언제·어떻게 연락하는지 안내 없음.
6. **1120px 이하에서 헤더 상담 CTA 소실** — 태블릿·모바일 전 구간에서 핵심 전환 버튼이 햄버거 메뉴 속으로 사라짐.
7. **전반적으로 과소한 글자 크기** — 폼 도움말 11.2px, 민감정보 경고 12px, 언어 링크 10px 등. 고령 타깃 대비 핵심 안내가 너무 작음.
8. **유효성 오류의 브라우저 기본 메시지 누출** — `tooShort` 커스텀 메시지가 message 필드에만 있고 name·phone에는 없어, 중국어 페이지에서 OS 언어의 기본 오류문이 뜰 수 있음.
9. **전화번호 국제 표기 부재** — en/zh 로케일에도 국내 표기·국내 tel 링크만 있어 해외 사용자는 연결 불가. `+82` 표기 필요.
10. **루트 404가 한국어 전용** — 로케일별 404는 빌드되지만 일반 호스팅은 `/404.html`(한국어)만 서빙. 영어 사용자 오타 접근 시 한국어 404.
11. **단일 언어 게시글에서 언어 전환 막다른 길** — 영어에만 있는 글에서 스위처가 English만 렌더링되어 다른 언어로 돌아갈 경로가 없음.

### Low 6건

- 날짜가 전 로케일 ISO(`2026-07-03`) 고정 표기 — `Intl.DateTimeFormat` 미적용
- 동의 문서를 `textContent`로 표시해 마크다운 문법 기호가 그대로 노출될 잠재 이슈
- 모바일 메뉴가 Escape/바깥 클릭으로 안 닫히고, 열림 상태에서도 레이블이 "메뉴 열기" 고정
- 언어 링크 컨테이너가 role 없는 div에 `aria-label`(보조기술에 전달 안 됨)
- 상담 분야 기본 옵션이 "—" 대시 하나
- 제출 성공 후 폼이 초기화되지 않고 버튼이 재활성화됨(서버는 중복 방지되지만 UI상 혼란)

### 잘 되어 있는 점

깨진 링크 0건·alt 누락 0건·헤딩 위계 정확(전수 스캔), hreflang/canonical/lang 속성 정확, 스킵 링크·focus-visible·reduced-motion 전면 대응, 폼의 aria-live/재시도/중복 방지 설계, 16px 입력 필드(iOS 확대 방지), 4개 언어 번역 구조 검증으로 누락 없음.

### 총평

기술적 기본기와 폼 상태 설계는 매우 탄탄하지만, "비전문·고령·다국어 모바일 사용자"라는 실제 타깃 관점에서는 작은 글자·대비 미달·모바일에서 숨겨진 언어 전환/CTA가 누적되어 체감 사용성이 설계 품질을 못 따라갑니다.

## B. 관리자 UI

결론: **관리자 화면이 세 영역 중 가장 취약**했습니다 — High 6건으로, 표현 계층이 사실상 "디버그용 뼈대 HTML" 수준. 백엔드 상태 설계는 견고.

### High 6건

1. **UI 전체가 영어 전용** (`routes.ts:91`) — 유일한 사용자가 한국어 사용 비기술 관리자인데 로그인·내비게이션·모든 오류 문구가 영어이고 `lang="en"` 하드코딩. 정작 고객용 철회 페이지는 4개 언어 완전 현지화되어 있음.
2. **로그인 실패 원인 구분 불가** (`routes.ts:81,352~`) — 비밀번호 오타·사전인증 만료·스로틀 잠금이 전부 같은 영어 문구 하나. 잠긴 상태에서 재시도를 반복해 잠금을 연장할 수 있음.
3. **내부 오류 코드 그대로 노출** (`routes.ts:560,584,609`) — 실패 시 `<h1>invalid-transition</h1>`, `slug-conflict`, `pii-rejected` 같은 코드가 오류 페이지의 전부이고 돌아가기 링크도 없음.
4. **세션 만료 시 입력 무경고 유실** — 유휴 30분/절대 8시간 만료 후 POST하면 로그인 페이지로 리다이렉트되며 SMTP 설정 같은 긴 폼 입력이 통째로 사라짐. 경고·복귀 경로 없음.
5. **CSRF/Origin 실패가 무설명 "Forbidden"** — 오래 열어둔 탭에서 저장 시 이유도 복구 방법도 없이 작성 내용 유실.
6. **CSS가 한 줄도 없음** — 상담 목록이 경계선 없는 테이블, 기사 상세가 마크다운 원문 `<pre>` 덤프, 시각 계층 부재.

### Medium 8건

- 파괴적 동작(기사 Reject — 복귀 불가 종착 상태, 릴리스 롤백)에 사용자 확인 단계 없음(confirmation이 hidden 필드)
- CAS 충돌 시 "Conflict" 한 단어만 표시, 현재 상태·복귀 경로 안내 없음
- MFA 화면에서 사용자명 재입력 요구, 코드 형식 안내 없음, 실패 시 비밀번호부터 재시작
- 알림 설정: 현황이 원시 JSON 덤프, email/hermes 폼 혼재로 상태 복사 혼동, **"Keychain reference" 개념 설명 전무**(비밀번호를 넣으면 invalid 처리되는데 그 이유를 알 수 없음)
- 설정 저장·테스트 발송 후 성공 메시지 없음, 테스트 결과는 Failures 페이지를 스스로 찾아가야 확인
- 상담 목록에 페이지네이션 링크 미렌더링 — 21건째부터 URL 수정 없이는 도달 불가
- 시각이 UTC ISO 표기 — 한국 관리자에게 9시간 어긋남
- **백업/복원 웹 UI 자체가 미구현** — 설계 문서만 존재. "파괴적 복원 확인" UX는 평가할 대상이 아직 없음

### Low 5건

개정판 비교에 diff 강조 없음, 슬러그 pattern에 title 없어 영어 기본 오류, 빈 상태 안내 없음, Health 페이지 원시 JSON, 알림 체크박스가 수신자(고객/소유자) 미설명.

### 잘 되어 있는 점

전 출력 `escapeHtml` 일관 적용(XSS 견고), 모든 POST가 PRG 패턴(새로고침 중복 제출 없음), 유효한 다음 상태만 노출하는 전이 제한, label/autocomplete 등 접근성 기본기, 게시/롤백 실패 페이지의 결과 보장 문구, 계정 존재 비노출.
